## 正式统计口径

- 只统计上表的新扫描 ID，项目聚合漏洞列表可能包含旧记录，因此不用于本次正式评测计数。
- 超时、部分完成、失败及未审查文件均保留在分母和结果中，不缩小范围后重跑来获得更好成绩。
- 已固定的已知问题与针对性负例作为人工核对锚点，可沿用同版本源码事实；旧扫描发现和成绩不作为正式扫描的命中依据。
- 按问题行为和源代码位置匹配，每个已知案例只计一次；额外发现独立核对，不能因为未列入锚点就认定误报。
- 按实际审查/失败/跳过文件、执行时间（排除排队）、token 用量、规范化发现、明确误报、重复和证据不足分别统计。
- 这是单次默认整仓评测，不据此宣称生产仓库的总体召回率、多次运行稳定性或动态可利用性。

## 评测结论

目前适合辅助人工白盒审查，尚不适合把默认整仓输出直接当成可信、完整的漏洞清单。

- **发现能力有价值，但覆盖完成不代表不漏报。** NodeGoat 命中 10/10 预设案例；VAmPI 完成全部文件仍漏未授权改密码和登录枚举。
- **噪声与误报需要治理。** 同一根因在路由、数据层、模板重复输出。已核实存在依赖默认配置误判、错误变量到危险点的关联、没有攻击者输入链的注入判断，以及开放重定向严重级别夸大。具体发现 ID、源码位置和依赖官方依据在项目 review 中。
- **默认配置的大仓库交付存在明显限制。** WebGoat 在默认 30 分钟内完成约 20%，早期时间花在 CSS、HTML、集成测试和框架代码；核心案例文件未开始。超时后有进度、无可用发现，零结果不能解释为安全。

后续优先考虑逐文件结果持久化、整仓内文件优先级和执行时限配置，再改善安全发现与一般建议的呈现、跨文件根因去重及依赖版本/调用链核对。这些建议不改变本次评测范围，也没有在本次实现漏洞修复验证或续传。

## 核验与限制

三个项目及扫描快照的范围字段均已清空；三个正式扫描均结束，没有排队/运行任务。Markdown、JSON、SARIF 报告接口均返回 200，JSON/SARIF 可解析；WebGoat 返回的是失败记录，不是完整分析。扫描源码工作目录已清空。核验记录见 [verification.json](verification.json)，机器可读汇总见 [summary.json](summary.json)。

未逐条验证 374 条发现，不给出总体准确率。靶场存在明确漏洞注释和课程标签，结果不能外推到生产代码。没有测试运行稳定性、增量扫描或修复验证。旧局部结果只留作参考，正式统计没有混用。
